# WO-013 · Cached card artwork and custom-label grade stickers
Scope: optional exact card selection on purchase entry/edit; lazy thumbnails in Home/History; tap thumbnail for large artwork and zoom. Parse PSA/CGC grades from the existing custom type without claiming verification. Existing purchases can attach artwork through Edit purchase; never guess a printing from a name. Preserve all financial data, imports, exports and app identity.
Research: existing inactive gallery used TCGdex and native image loading. TCGdex official docs recommend low WebP (245x337) for lists and high WebP (600x825) for details, with explicit paginated name searches. Inspected MIT database license, source and maintenance (pushed 2026-11-15, not archived); no SDK/dependency installed. API needs no key. MDN Cache API reviewed: storage is evictable and must not contain sole copies of records. Live probes found some artwork has malformed CORS headers; try readable cacheable fetch then display uncached if necessary, never persist opaque responses with oversized quota padding.
Plan: small standalone artwork module, selected metadata in each transaction, explicit paginated search with abort/timeout and session reuse, native lazy images, independent bounded service-worker artwork cache retained across app releases. No polling, bulk backfill, prices, camera, or paid services. Logos bundled locally with source attribution, used as identification only.
Acceptance: exact match selected and retained across edits/reload/backup; no artwork or API dependency required to save; safe image host/path validation; grade parsing positive/negative/ambiguous cases; cached/offline reuse, limits and failure handling; mobile widths/touch preview; accounting regressions unchanged. CI and live asset/deployment checks required.
